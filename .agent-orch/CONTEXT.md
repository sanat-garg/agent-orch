# Project Context

_Durable knowledge for every agent session: architecture, conventions, decisions, gotchas. History lives in JOURNAL.md._

## Architecture
- `server.mjs`: node:http + `ws`. Login/sessions (cookie `__Host-cw_session` over HTTPS via `X-Forwarded-Proto`, plain `cw_session` on http), chat via the Agent SDK `query()`, serves `public/`. PORT defaults to 3000. Chat runtimes: always `retireRuntime` (runtimes.mjs), never `q.close()` + `runtimes.delete`.
- `orchestrator.mjs`: node:sqlite DB at data/orchestrator/agent-orch.db; planner/worker/reflection loop; `runAgent()` wraps adapters with timeout + run log. Prompts live inline. `createOrchestrator({config})` overrides CFG in tests.
- `agents.mjs`: adapter registry (`AGENTS`, `runAgentCli`) emitting normalised events (text/tool/tool_result/result/limit). Adapters: claude (SDK) and codex (`codex exec --json`) only: Antigravity, OpenCode, Kiro and Copilot were uninstalled and their code removed (owner, 2026-09-27); never re-add them. CLI adapters share `spawnJsonl` (detached process group, killed on abort/exit). Normalisers build tool inputs with `toolInput`/`nativeInput` and results with `toolResult` (never `{}`/`""` when the native event had data; test/empty-events.test.mjs invariant); `runAgentCli` turns an ok run with no reply into last text / a marked tool summary / `empty_response` error. `bin/empty-scan.mjs` audits logs. `agentStatus` (on PATH + logged in, cached 60 s) gates routing. CLI flags and stream formats: `.agent-orch/AGENTS.md`.
- `models.mjs`: every model list comes from its CLI (`discoverModels`), cached in `<DATA>/models.json`. Each discovery starts a CLI, so a list is rediscovered only once it is a day old (`MODELS_TTL`, checked hourly, one agent at a time) or after that agent's sign-in changes; at most once per agent per 60 s. Read via `modelCatalog(id)`/`modelNames(id)` (reads never discover); never hardcode model lists.
- `helpers.mjs` (#211): every discovery/limit/sign-in helper (not agent runs) goes through `runHelper`/`helperOut` (async), `runHelperSync` (coreutils `timeout` wrapper) or `claudeHelperSpawn` (SDK `spawnClaudeCodeProcess`). Own process group, group kill SIGTERM→SIGKILL 3 s on timeout/abort/exit, exit hook + per-group `sh` watchdog so nothing outlives the parent. `discoverModels`/`fetchLimits`/`readVersion` are single-flight per agent+account. Never add raw execFile/spawnSync helpers.
- Routing (`resolveRoute`): task agent/model → project route → global route → Claude on project.model. Model-only routes infer the agent; a model the agent doesn't list is dropped. Unavailable agents fall back to Claude with `tasks.route_note`. Sessions resume only on the agent that made them (`runs.agent`).
- Limits are per agent (`limitScope(agent)`): `blockedUntilFor(agent)`; kv keys `blocked_until`/`blocked_known`/`blocked_reason` (+ `:<agent>` suffix for non-Claude). `claimNext` skips only tasks whose resolved agent is blocked.
- Delegation (`delegate.mjs`): no benchmarks. A task moves only if its `tasks.fallbacks` snapshot is non-empty (null/[] = wait). `nextModel` picks the first entry whose agent is connected, lists the model, isn't blocked and has no window ≥90%. Lists: `convo.fallbacks` (per chat) and `projects.reflect_fallbacks`. Queued/running work snapshots can be edited via PATCH /api/orch/tasks/:id/fallbacks; running workers read the saved list on resume/limit handling. Moves are appended to `tasks.moves`. UI text comes only from app.js `modelStatus(task)`.
- Planner: `planTurn` runs on the chat's agent; `planningProjects` allows one planner resume per project; messages during a plan task go through `deferMessage`. Saved messages: pending → taken (by a plan task) → done.
- Worktrees: work tasks in a git project run in `<repo>/../.agent-orch-worktrees/<repo>-task-<id>` on branch `agent-orch/task-<id>` (worktrees.mjs; node_modules symlinked from the main tree, worktree removed right after merge). Only `mergeTask` touches the main tree, under `serialGit` (squash, rebase, ff-only, push). Rebase conflict → `needs_integration` + an integrator task in the same worktree; `releaseOwner` fails/cancels the owner with its integrator. JOURNAL.md merges with `merge=union`. Tasks may declare `files` (NULL = everything); `runnable` shares a project only when `filesOverlap` is false. Deps: `task_deps` table, read via `depsOf(id)` / the `all_deps` view (legacy `tasks.depends_on` = first dep).
- Slots (#207, BRIEF goal 9): ONE work task at a time across all projects by default (plan tasks run beside it). kv `parallel_settings` `{parallelTasks: 1|2}` (PUT /api/orch/parallel); 2 only while /proc/meminfo MemAvailable > 2.5 GB and swap < 25% (parallel.mjs `taskSlots`/`readMemInfo`, re-read per claim; `CFG.meminfo`, env `AGENT_ORCH_MEMINFO` set to a fixture by bin/test.mjs). MemAvailable < 800 MB → no claims; < 300 MB for 30 s → `memGuard` aborts the newest work task (requeued, resumes). `CFG.agentSlots` (1/account) still makes a second task spill to a fallback (`spreadAssign`). State exposes `parallel`, `slots`, `workRunning`, `lanes` (each with `project_id`). The UI shows no lanes (removed from the Queue window 2026-09-27 at the owner's request; `olane` broadcasts are ignored); `lanes` + running tasks only drive the sidebar's blue running-project dot (app.js `runningProjectIds`).
- `resources.mjs` (#208): /proc snapshot every 10 s (per-process RSS/PSS/CPU%, trees + categories) and the reaper (only `REAP` categories past their age; never live server/task/chat/owner terminal/system/other users; never signals a process group that contains a protected pid). Ownership = env `AGENT_ORCH_OWNER=<server pid>:task|chat:<id>` set by runAgent/chat turns (inherited by descendants) + `registerPid` via runAgentCli `onSpawn`; a marker from another live server is ignored, so test instances never reap live work. `AGENT_ORCH_REAPER=on|dry|off` (default on; dry with CW_DATA_DIR; off with CW_NO_ORCHESTRATOR). Log: `<DATA>/metrics/reaper.jsonl` + events. API: GET /api/resources, POST /api/resources/kill {pid}. Orchestrator reaps before claiming when MemAvailable < `MEM.reapBelow`.
- Queue order: `tasks.position` (per project) first; plan/reflect/user tasks and deadlines <24 h jump ahead.
- `connections.mjs`: web sign-in; runs each CLI's login in tmux (socket `-L agent-orch-login`) and scrapes the pane. Every server boot kills that socket (a test server kills the live app's pending logins too).
- `usage.mjs`: append-only `<DATA>/metrics/usage.jsonl` (30 days). Non-Claude windows come from adapters (`res.windows`); missing readings never inherit Claude's. Each adapter's `limitSource` + `limits()` (null = 'not exposed by CLI') feed `fetchLimits`/`createLimitStore` (`<DATA>/limits.json`). Nothing polls limits (owner, 2026-09-27: CPU): only the sidebar usage card's refresh checks the one agent it shows (`POST /api/limits/:id/refresh`, or the Claude probe over the socket); orchestrated Claude runs report limits as they go; `health.mjs` `healthRow` builds the Connections rows' `health` and `bin/agent-health.mjs` (sources: AGENTS.md).
- `media.mjs`: screenshots stored as `<DATA>/media/<sha256>.<ext>`, served by `GET /api/media/:id`. `bin/shot.mjs` (playwright-core 1.63.0 = cached chromium-1243) takes them; save into `<project>/.agent-orch/shots/`.
- `github.mjs`: gh wrapper; every project gets a private repo on `origin`.
- `public/`: vanilla JS SPA (app.js ~4.5k lines, marked + dompurify), PWA. Shared helpers: `toast(msg, {kind, action, run, duration})`, `renderFallbackEditor`, `withUntil`, `fmtDur`. Check for name clashes before adding functions (a later declaration silently wins).
- Live setup: systemd units agent-orch, agent-orch-shell (ttyd 127.0.0.1:7682, Caddy `/shell/`), agent-orch-tmux. `data/` (gitignored) holds auth, convos, metrics, logs, DB, run logs.

## Conventions
- ESM `.mjs`, no build step, no framework, minimal deps. Match the terse style and comment density.
- Tests: `node --test`; `npm test` runs `test/**/*.test.mjs` via bin/test.mjs, with a private TMPDIR under node_modules/.cache that is removed afterward. Fixture servers with temporary homes use isolatedPath: system PATH exposes real agent CLIs, whose bootstrap downloads can exhaust /tmp quotas. Server tests spawn server.mjs on a free port with `CW_DATA_DIR` set to a temp dir. Scheduling tests run `createOrchestrator` in a child process with a fake `query`; CLI adapters use stub binaries in test/fixtures/. Scheduler tests pass `config: { pollMs: 100 }` and poll with `test/helpers/wait.mjs` instead of fixed sleeps. Browser tests (test/ui-*.test.mjs) use playwright-core.
- User-visible times: events carry `until` (epoch s); app.js `withUntil` formats in the browser's timezone. Don't format times on the server except in logs.
- .agent-orch/AUDIT.md is the bug backlog; mark fixed items `**Fixed**` with a one-line note.
- Mobile: follow Apple HIG (apple-design skill). Modals need `grid-template-columns: minmax(0, 100%)`; test/ui-away.test.mjs checks every modal fits 375×667 and 390×844.

## Decisions
- Chat and agents run on subscriptions, never API credits (API_ENV stripping in server.mjs). Never weaken that.
- Repo is github.com/sanat-garg/agent-orch with fresh history; local branch `backup/pre-agent-orch` must never be pushed.
- `after` is for TRUE prerequisites only: cancelling a task cascades to everything after it. Use `files` to keep work apart.
- Typography uses the system font stack; no bundled web fonts (Inter was tried and reverted).
- Delegation is owner-entered fallback lists only; benchmark ranking was removed on purpose.

## Gotchas
- Disk (2026-09-26, #207): leaked test temp dirs filled the per-user quota on tmpfs /tmp (`usrquota`, EDQUOT). Cleanup: `/` 12G used/33G free → 11G/34G; /tmp 843M/11.5k entries → 348M/440. Tests that bypass `npm test` leak `codex-test*` dirs into /tmp.
- This checkout IS the live app. Never restart/kill it or call `POST /api/restart-when-idle` on port 3000. Test instances MUST use another port and `CW_DATA_DIR=$(mktemp -d)`, or they double-run live tasks. `CW_NO_ORCHESTRATOR=1` serves read APIs without the tick loop.
- Server/orchestrator edits go live only on restart ("Restart when idle" banner). A failing "Done when" check may be stale running code, not the task.
- The verifier runs every command-like backtick snippet in "Done when", joined with ` && `. Commands containing `>` (incl. `2>&1`) or `curl` are refused. Absence checks use `! grep …`.
- Claude logout needs `confirm: true` — never send it in tests.
- `bin/agent-smoke.mjs --agent X --model Y [--log dir]` and `bin/orch-e2e.mjs --agent X --model Y [--parallel]` are live checks (cost quota).
- The screenshot lightbox `#lbView` needs `contain: size` or huge images widen the modal.
- Don't commit macOS `._*` files.
- /tmp is a small tmpfs with a per-user quota that other tasks' test homes (cw-*-home-*) fill; run heavy tests/smokes with `TMPDIR=` on the home disk.
- 2026-09-26: The owner wants the orchestrator bar above the composer (#orchBar) kept minimal: one short status line plus exactly three buttons (Queue, Settings, Pause/Resume). Don't add chips, lanes, counts or limit text to it; put new info in the Queue modal, the Settings popover or Server details.
