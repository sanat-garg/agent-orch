# Project Context

_Durable knowledge for every agent session: architecture, conventions, decisions, gotchas. History lives in JOURNAL.md; the bug backlog in AUDIT.md; the cluster design in CLUSTER.md; CLI flags and stream formats in AGENTS.md._

## Architecture (head / controller)
- `server.mjs`: node:http + `ws`. Login/sessions (cookie `__Host-cw_session` over HTTPS via `X-Forwarded-Proto`, plain `cw_session` on http), chat via the Agent SDK `query()`, serves `public/`. PORT defaults to 3000. Chat runtimes: always `retireRuntime` (runtimes.mjs), never `q.close()` + `runtimes.delete`. Every response sends `frame-ancestors 'none'` + `X-Frame-Options: DENY`.
- `orchestrator.mjs`: node:sqlite DB at data/orchestrator/agent-orch.db; planner/worker/reflection loop; `runAgent()` wraps adapters with timeout + run log. Prompts live inline. `createOrchestrator({config})` overrides CFG in tests. Deps: `task_deps` table via `depsOf(id)` / the `all_deps` view. Queue order: `tasks.position` per project; plan/reflect/user tasks and deadlines < 24 h jump ahead.
- `agents.mjs`: adapter registry (`AGENTS`, `runAgentCli`) emitting normalised events (text/tool/tool_result/result/limit). Adapters: claude (SDK) and codex (`codex exec --json`) only. CLI adapters share `spawnJsonl` (detached process group, killed on abort/exit). Normalisers use `toolInput`/`nativeInput`/`toolResult` and must never emit `{}`/`""` when the native event had data (test/empty-events.test.mjs); an ok run with no reply becomes last text / a tool summary / `empty_response`. `agentStatus` (on PATH + logged in, cached 60 s) gates routing.
- `models.mjs`: every model list comes from its CLI (`discoverModels`), cached in `<DATA>/models.json`, rediscovered once a day per agent or after a sign-in change. Read via `modelCatalog(id)`/`modelNames(id)` (reads never discover). Never hardcode model lists.
- `helpers.mjs`: every discovery/limit/sign-in helper (not agent runs) goes through `runHelper`/`helperOut`, `runHelperSync` or `claudeHelperSpawn`: own process group, SIGTERM→SIGKILL, watchdog so nothing outlives the parent; single-flight per agent+account. Never add raw execFile/spawnSync helpers.
- Routing (`resolveRoute`): task agent/model → project route → global route → Claude on project.model. Model-only routes infer the agent; unlisted models are dropped; unavailable agents fall back to Claude with `tasks.route_note`. Sessions resume only on the agent (and node) that made them.
- Limits are per agent (`limitScope`, `blockedUntilFor(agent)`; kv `blocked_until`/`blocked_known`/`blocked_reason` + `:<agent>` suffix for non-Claude). `claimNext` skips only tasks whose resolved agent is blocked. Nothing polls limits: only the sidebar usage card's refresh (`POST /api/limits/:id/refresh`) checks the one agent it shows; orchestrated Claude runs report limits as they go. `usage.mjs` = append-only `<DATA>/metrics/usage.jsonl`; `health.mjs` builds the Connections rows' `health`.
- Delegation (`delegate.mjs`): no benchmarks. A task moves only if its `tasks.fallbacks` snapshot is non-empty (null/[] = wait); `nextModel` picks the first entry whose agent is connected, lists the model, isn't blocked and has no window ≥ 90%. Lists: `convo.fallbacks` per chat, kv `reflect_settings` (beats `projects.reflect_fallbacks`) for reflection. Moves append to `tasks.moves`; UI text comes only from app.js `modelStatus(task)`.
- Owner controls: POST /api/orch/tasks/:id/pause|resume|handoff set `stopIntents`; `applyStopIntent` applies them only if the run ended requeued. 'paused' keeps session + worktree and pins agent/model. Handoff gives the next fresh session `ownerHandoffPrompt` (run-log tail, git status, diff --stat). Remote tasks can be paused but not handed off while running.
- Planner: `planTurn` runs on the chat's agent; `planningProjects` allows one planner resume per project; owner messages during a plan task go through `deferMessage` (pending → taken → done).
- Worktrees (worktrees.mjs): work tasks in a git project run in `<repo>/../.agent-orch-worktrees/<repo>-task-<id>` on branch `agent-orch/task-<id>` (node_modules symlinked; removed right after merge). Only `mergeTask` touches the main tree, under `serialGit` (squash, rebase, ff-only, push). Rebase conflict → `needs_integration` + an integrator task in the same worktree. JOURNAL.md merges with `merge=union`. `tasks.files` (NULL = everything) + `filesOverlap` decide what may share a project in parallel.
- Slots (parallel.mjs): kv `parallel_settings` `{parallelTasks: 1|2, controllerWork: bool, maxTasks: null|n}` (PUT /api/orch/parallel). The controller runs 2 only while MemAvailable > 2.5 GB and swap < 25% (`taskSlots`/`readMemInfo`, env `AGENT_ORCH_MEMINFO` = fixture in tests); < 800 MB → no claims; < 300 MB for 30 s → `memGuard` aborts the newest work task. With workers online and `controllerWork` false (default) the controller leaves remotable tasks to workers. `capacityView` sums controller + worker slots, pacing and the owner's `maxTasks` cap. Lanes exist in state only for the sidebar's running-project dot; the UI shows no lanes.
- `resources.mjs`: /proc snapshot every 10 s and the reaper (only `REAP` categories past their age; never live server/task/chat/owner-terminal processes; ownership = env `AGENT_ORCH_OWNER=<server pid>:task|chat:<id>` + `registerPid`, markers from other servers are ignored). `AGENT_ORCH_REAPER=on|dry|off`. API: GET /api/resources, POST /api/resources/kill.
- Review breaks: `kind='review'` tasks never run; `armCheckpoints()` moves one whose deps are done to `awaiting_review`, holding its dependents; approve → done; request-changes queues a fix task into the checkpoint's deps. Blocking is by dependency only.
- `connections.mjs`: web sign-in runs each CLI's login in tmux (socket `-L agent-orch-login`) and scrapes the pane; every server boot kills that socket. `remote-login.mjs`: `?node=<id>` on /api/connections* proxies login.start/code/cancel/logout to a worker (`createRemoteLogins` head side, `createNodeLogins` worker side, socket `agent-orch-worker-login` or a `script` pty). Rows carry `sharedWith` (machines on the same account share limits).
- `extensions.mjs` (Settings → Skills & tools, `public/ext.js`): skills go where the CLIs discover them (`~/.claude/skills/<name>/SKILL.md`, `~/.codex/skills/<name>/`), subagents to `~/.claude/agents/` (Claude only); MCP servers and personas in `<DATA>/extensions/` (0600, secrets masked by the API). MCP reaches runs through files, never argv: Claude `extraArgs {'mcp-config': …}`, codex `codex -p agent-orch …` (`-p` before `exec`). Persona = `convo.persona`, appended to the chat system prompt and, via `withPersona`, to planner/task/remote-job system text. Remote workers get the persona but not skills/subagents/MCP yet.
- `stats.mjs` + `public/stats.js`: GET /api/stats returns raw records (own read-only DB connection, cached 30 s); the browser slices by range/project. A run's model comes from its run log's first line, else `runModel`.
- `media.mjs`: screenshots at `<DATA>/media/<sha256>.<ext>`, `GET /api/media/:id`; `bin/shot.mjs` (playwright-core, cached chromium) takes them into `<project>/.agent-orch/shots/`.
- `github.mjs`: gh wrapper; every project gets a private repo on `origin`.
- `public/`: vanilla JS SPA (app.js ~6.9k lines, marked + dompurify), PWA. Shared helpers: `toast(msg, {kind, action, run, duration})`, `renderFallbackEditor`, `withUntil`, `fmtDur`. Check for name clashes before adding functions (a later declaration silently wins). The orchestrator bar (#orchBar) stays minimal: status dot + one word + Queue and Pause/Resume; everything else lives in the sidebar gear's Settings sheet (#settingsModal: sound, max parallel tasks, reflection model + fallbacks, Keep improving, reflection direction).
- Live setup: systemd units agent-orch, agent-orch-shell (ttyd 127.0.0.1:7682, Caddy `/shell/`), agent-orch-tmux. `data/` (gitignored) holds auth, convos, metrics, logs, DB, run logs.

## Architecture (cluster)
- `cluster-protocol.mjs`: wire format, validators, pairing/token helpers, `FEATURES` (a newer frame type goes only to a peer that lists the feature in `hello`/`welcome`) and `WORKER_ACCEPTS` (the only frames a worker acts on; the hub's `send` throws for anything else). Change the protocol here first; CLUSTER.md follows the module.
- `cluster.mjs` (head hub): `nodes` + `pairings` tables (codes hashed, multi-use `{uses: 2..20}` valid 1 h), bearer-token WS at `WS_PATH` (separate `WebSocketServer`, no cookies), local node id `controller`, `listNodes()`/`send()`/`onMessage()`/`version()` (orchestrator `nodesNow()` caches 1 s but re-reads when the version moves). `HEALTH` auto-drain rules; self-update of workers > 20 commits behind `origin/main` once idle. `CW_CLUSTER_HEARTBEAT_MS` shortens liveness in tests. `power.mjs`: Mac battery/sleep policy (`nodes.policy`, `welcome.policy`/`node.policy`); `resources.intake.ok === false` shows the node as paused.
- `worker.mjs` (compute-only daemon: `pair`/`run`/`status`/`limit`), home `~/.agent-orch-worker` (`AGENT_ORCH_WORKER_HOME`). It must never import server/orchestrator/cluster/runtimes (shared code goes in taskrun.mjs; test/compute-only.test.mjs walks the import graph). Sends job.check before job.done, drops the worktree after job.done (job.resume re-creates it from the pushed branch). `cap.mjs`/`worker-cap.mjs`: the one local setting (`limit`), every job runs through a `<home>/run` wrapper (systemd scope or nice; tests set `AGENT_ORCH_WORKER_LIMITER=nice`). `worker-status.mjs`: `worker.sock` (0600) is the only listener allowed. `node-metrics.mjs`: telemetry kept in `<DATA>/metrics/nodes/<id>.jsonl`. server.mjs refuses to start on a paired worker (role.mjs `headRefusal`) unless `AGENT_ORCH_WORKER_JOB` is set.
- Placement (orchestrator `place`/`runRemote`/`remoteJob`, wired by `orch.attachCluster`): `claimNext` returns `{task, node, prevNode}`; a work task goes to the free online worker with the agent signed in and the most headroom (`nodeCap`: `max_slots`, or Auto = min(cores − 1 on a Mac, RAM above `max(claimFloor, reserveGB)` / footprint)), else the controller. Only `remoteWork` tasks go remote (`assertPlacement`): plan/reflect/integrators, tasks with a live local worktree and projects without an https/ssh `origin` stay local. `tasks.node_id`/`runs.node_id` record placement. On job.done the head fetches `agent-orch/task-<id>` (tip must equal job.done.sha) into a local worktree and runs `mergeTask`, then deletes the remote branch. Per-job event streams replay via `job.attach {from}` after reconnects; lost jobs (grace = `nodes.grace_ms`) requeue with `[lost]` and a `handoffPrompt` from the pushed WIP branch; remote tasks survive a head restart (`adopt`). `job.phase` → `runs.phases`, `job.error` → `runs.errors`.
- Install + UI: Server details → Machines → "Add machine" (app.js `AM`) shows `curl …/install/worker-{linux,macos}.sh | bash -s -- --controller … --code …` (served pre-auth, fresh from disk, from bin/install-worker*.sh; both support `--dry-run`) and watches GET /api/cluster/pair/:code. macOS runs the worker as user `agentorch` from a LaunchDaemon (`--service login` = the owner's LaunchAgent). Machines view (app.js, GET /api/cluster/nodes decorated by `orch.machines()`): one card per node, `max_slots` 0 = Auto, drain, remove; the cluster diagram (`CA`) is fed only by data the page already gets. Node modal (`ND`): metrics charts, phases, log tail.

## Conventions
- ESM `.mjs`, no build step, no framework, minimal deps. Match the terse style and comment density.
- Tests: `npm test` runs `test/**/*.test.mjs` via bin/test.mjs with a private TMPDIR under node_modules/.cache. Fixture servers with temporary homes use isolatedPath (the real CLIs' bootstrap downloads exhaust /tmp). Server tests spawn server.mjs on a free port with `CW_DATA_DIR` set to a temp dir; `CW_NO_ORCHESTRATOR=1` serves read APIs without the tick loop (and `machines()` then has no phases). Scheduling tests run `createOrchestrator` in a child process with a fake `query`, `config: { pollMs: 100 }`, and poll with `test/helpers/wait.mjs`. CLI adapters use stub binaries in test/fixtures/. Browser tests (test/ui-*.test.mjs) use playwright-core; test/ui-cluster-anim.test.mjs feeds frames through `routeWebSocket`. Worker tests run worker.mjs against an in-process `createCluster` hub (worker CLI calls must be async, execFileSync deadlocks it), pass `health: {diskMinBytes: 0}` (/tmp has < 2 GB free), point `AGENT_ORCH_WORKER_SRC` at a scratch repo, and fake a Mac with `AGENT_ORCH_WORKER_POWER` + `AGENT_ORCH_WORKER_CAFFEINATE`.
- User-visible times: events carry `until` (epoch s); app.js `withUntil` formats in the browser's timezone. Don't format times on the server except in logs.
- .agent-orch/AUDIT.md is the bug backlog; mark fixed items `**Fixed**` with a one-line note. .agent-orch/UI-REVIEW.md lists the mobile HIG findings; mark each one fixed in its row.
- Mobile: follow Apple HIG (apple-design skill). Modals need `grid-template-columns: minmax(0, 100%)`; test/ui-away.test.mjs checks every modal fits 375×667 and 390×844.
- Shell scripts meant for macOS must parse under bash 3.2 (see Gotchas) and be tested with `~/.local/opt/bash-3.2.57/bin/bash`.

## Decisions
- Chat and agents run on subscriptions, never API credits (API_ENV stripping in server.mjs). Never weaken that.
- Claude Code and Codex are the only agents; Antigravity, OpenCode, Kiro and Copilot were removed for good. Never re-add them.
- Repo is github.com/sanat-garg/agent-orch with fresh history; local branch `backup/pre-agent-orch` must never be pushed.
- `after` is for TRUE prerequisites only: cancelling a task cascades to everything after it. Use `files` to keep work apart.
- Typography uses the system font stack; no bundled web fonts (Inter was tried and reverted).
- Delegation is owner-entered fallback lists only; benchmark ranking was removed on purpose.
- Workers are compute-only: no chat, planner, settings or web UI on a worker; the terminal status view and the local cap are its only local surface.
- Nothing polls the CLIs on a timer (CPU): limits on demand, model lists once a day.

## Gotchas
- This checkout IS the live app. Never restart/kill it or call `POST /api/restart-when-idle` on port 3000. Test instances MUST use another port and `CW_DATA_DIR=$(mktemp -d)`, or they double-run live tasks and kill the live app's pending tmux logins.
- Server/orchestrator edits go live only on restart ("Restart when idle" banner). A failing "Done when" check may be stale running code, not the task.
- The verifier runs every command-like backtick snippet in "Done when", joined with ` && `. Commands containing `>` (incl. `2>&1`) or `curl` are refused. Absence checks use `! grep …`; a bare `grep 'a|b' f` "prints nothing" is mis-rewritten by the live verifier until the taskrun.mjs fix from task #244 is merged and the server restarted.
- /tmp is a small tmpfs with a per-user quota (EDQUOT) that other tasks' test homes fill; run heavy tests/smokes with `TMPDIR=` on the home disk. Tests that bypass `npm test` leak `codex-test*` dirs into /tmp.
- test/helper-kill.test.mjs "nothing outlives the parent" is racy under load: it can leave `test/fixtures/helper-parent.mjs` running and hang `npm test`, holding the test lock every worktree shares. Kill that pid to let the suite go on.
- Playwright `hover()` scrolls the target into view and the `scroll` event lands a few ms after `pointermove` on this 1-core box; tooltips that hide on scroll flicker (stats.js `wireTips` re-targets instead). Do the same for new tooltips.
- Claude logout needs `confirm: true` — never send it in tests. `bin/agent-smoke.mjs` and `bin/orch-e2e.mjs` are live checks that cost quota.
- The screenshot lightbox `#lbView` needs `contain: size` or huge images widen the modal. Don't commit macOS `._*` files.
- macOS runs installers with /bin/bash 3.2.57. Its `declare -f` prints `cat <<EOF | cmd` with the `| cmd` AFTER the EOF line, so functions shipped via `bash -c "$(declare -f)"` fail to re-parse; write `cmd <<EOF` instead. Under `set -u`, bash 3.2 also treats an empty `"${arr[@]}"` and an empty `"${BASH_SOURCE[0]}"` (script piped to bash) as unbound. No `declare -A`, `mapfile`, `${x,,}`, `|&`, `;;&`, `local -n`. Build the binary with bin/dev/build-bash32.sh (from the task-244 branch) to `~/.local/opt/bash-3.2.57/bin/bash`; the bash 5 on this server hides these bugs.
- Other sessions and orchestrator auto-commits touch the live checkout at once: re-read a file before editing it, keep shared test edits minimal. A branch failing in files you didn't touch usually means a stale snapshot base: fast-forward the worktree to main and re-run.
