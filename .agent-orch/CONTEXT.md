# Project Context

_Durable knowledge for every agent session: architecture, conventions, decisions, gotchas._

## Architecture
- `server.mjs`: node:http + `ws`. Login/sessions (cookie `cw_session`), chat via the Agent SDK `query()`, serves `public/`. PORT defaults to 3000.
- `orchestrator.mjs`: node:sqlite DB at data/orchestrator/agent-orch.db; planner/worker/reflection loop; `runAgent()` wraps the adapters and adds timeout + the task-run log. Prompts live inline.
- `agents.mjs`: adapter registry (`AGENTS`, `runAgentCli`) emitting normalised events (text/tool/tool_result/result/limit). Adapters: `claude` (SDK), `codex` (`codex exec --json`), `antigravity` (`~/.local/bin/agy -p --output-format stream-json`; refuses Gemini API-key mode). CLI adapters share `spawnJsonl` (detached process group, killed on abort and after exit). `agentStatus` (on PATH + logged in, cached 60 s) gates routing. `isMissingSession` detects dead resumes.
- Routing (`resolveRoute`): task's own agent/model → project route → global route → Claude on project.model. A model-only route infers the agent from the model family; a foreign model on an explicit agent is dropped. Unavailable/unsigned/limited agents fall back to Claude with `tasks.route_note` (UI badge). Planner always runs on Claude. Sessions resume only on the agent that made them (`runs.agent`).
- Limits are per agent: `blockedUntilFor(agent)` / `limitResetFor(agent)`; Claude keeps kv `blocked_until`/`blocked_known`/`blocked_reason`, others use the same keys + `:<agent>` (plus `agent_auth_failed:<agent>`). `claimNext` skips only tasks whose resolved agent (`agentFor`) is blocked. `planTurn` runs the planner on the chat's `convo.agent` (plan tasks carry it in `tasks.agent`; non-Claude planner sessions in kv `planner_session:<pid>:<agent>`); a per-message `autoDelegate` (WS `send`) lets it answer on another agent with a notice. `stateView().blocks` = `{agent: {until, known, reason}}`; task views carry `runs_on`.
- Chat agents: `convo.agent` + `convo.model` (WS `set_model`). Non-Claude chats run one `runAgentCli` turn per message (`agentChatTurn`, resume via `convo.agentSession`).
- Planner guard: `planningProjects` ensures only one `--resume` of a project's planner session at a time; chat messages during a plan task go through `deferMessage`.
- Saved messages (`messages` table): status pending → taken (plan task claims them in one `UPDATE … RETURNING`, `task_id`; back to pending if the run isn't ok) → done. 'Saved…' notices carry `msgId`; `changeMessage` backs PATCH/DELETE `/api/orch/messages/:id` (409 unless pending; retracting the last one cancels the queued plan task) and emits chat events `msg_edit`/`msg_retract`/`msg_state` that app.js `markPending` & co. replay onto the preceding user bubble.
- `connections.mjs`: web sign-in. Runs each CLI's login in tmux (socket `-L agent-orch-login`), scrapes the pane with per-agent `SPECS`, detects the end via an `__AO_EXIT:<code>` marker (agy never exits: `liveSuccessRe`/`liveFailRe`). API: GET /api/connections, POST /api/connections/:id/{start,code,cancel,logout}; WS `{t:'connections'}`. Claude logout needs `confirm: true` — never send that in tests. agy has no logout subcommand: its login is the file `~/.gemini/antigravity-cli/antigravity-oauth-token` (`id_token` gives the email via `agyAccount`); `agyLogout` deletes only that file — never call it on the real home in tests. Every server boot (test instances too) kills the whole login tmux socket. UI: `#connsModal`, opened by the sidebar footer button `#connFoot` ("Connected", plus "· X signed out" only for an agent in use: chat pick or routing rules) and `openConnections(id)`.
- `media.mjs`: agent screenshots. Tool-result base64 images (claude adapter yields raw `{k:'image',tool,mediaType,data}`) and new/changed files in `<project>/.agent-orch/shots/` (`mediaCollector` per turn/run) are stored as `<DATA>/media/<sha256>.<ext>` (format sniffed from bytes, ≤10 MB) and logged as `{t:'image',id,name,w,h,tool?}` in chat logs / `{k:'image',…}` in run JSONL. Served by login-protected `GET /api/media/:id` (id must match `MEDIA_ID_RE`). `bin/shot.mjs` (playwright-core pinned to 1.63.0 = cached chromium-1243) takes the shots; `SHOT_HINT` (orchestrator.mjs) tells workers and chats to use it. UI: app.js `shotNode`/`shotGrid` (chat `t:'image'`, drawer `k:'image'`) and the `#lightbox` modal (`openShot`).
- Sidebar usage follows active chat/task agents (`stateView().activeUsage`), rotates distinct subscriptions every 3 s, and reads non-Claude windows from `/api/usage/history`; missing/expired readings never inherit Claude values. Composer directory chip is commented out in `public/index.html`, with optional JS bindings retained for restoration.
- `usage.mjs`: append-only `<DATA>/metrics/usage.jsonl` (t epoch ms, resetsAt epoch s; kinds window/tokens/limit), 30 days, compacted at server boot. Server records Claude windows in `refreshUsage` and chat turns; orchestrator (`usageLog` option) records run tokens in `runAgent` and limit hit/cleared in `recordGovernor` + the 15 s block-expiry interval. Codex/agy plan windows arrive as adapter `res.windows` (codex: rollout token_count snapshot, `5h`/`weekly`; windowless `limit_id:"premium"` snapshots are skipped; server polls the newest rollout every 5 min while codex is idle, recording `at` = snapshot time; history status windows carry `stale`; orchestrator `reconcileCodexLimit` settles a reset-less codex hit at startup; agy: a follow-up `agy -p /usage`, `gemini-5h`/`3p-weekly`…) and are recorded next to the run/turn tokens via `usageLog.windows`. `GET /api/usage/history?range=24h|7d|30d` rereads the file per request. UI: `#usageModal` (app.js `U`, `openUsage`, opened by the sidebar `.ms-usage` card), charts via `usageChart` using the `.sline` styles; app.js already has `fmtDur(sec)`, so check for name clashes before adding helpers (a later function declaration silently wins). Test servers on this VM record the live Claude windows too.
- `models.mjs`: every agent's model list comes from its CLI (agents.mjs `discoverModels`; commands in AGENTS.md), cached in `<DATA>/models.json`, refreshed at boot, every 6 h and after a sign-in change (connections `afterChange`). Read lists via `modelCatalog(id)` / `modelNames(id)`; adapters have no `models` array. `/api/agents` gives `models: [{id,label,description?,default?}]` + `modelsError`; WS `{t:'models'}` makes the UI refetch. `resolveRoute` drops a model the agent's known list doesn't name.
- `aa.mjs`: Artificial Analysis metrics (API v2 `/language/models` with `/language/models/free` fallback on 403, header `x-api-key`, free tier 100 req/24 h; attribution required: `ATTRIBUTION` in every output). Key in `<DATA>/secrets.json` (0600, write-only via `/api/aa/key` GET/POST/DELETE) or `AA_API_KEY`; cache `<DATA>/aa-models.json`, 24 h TTL, honours 429 Retry-After. `matchModels` maps CLI models via `normName` + `.agent-orch/model-map.json` overrides; without a key `.agent-orch/model-metrics.json` is used (source `manual`). `GET /api/models/metrics` adds `data_status` (loading/unconfigured/error/ready), safe `data_error`, and `stale`; delegate preview forwards them to the popup. Verified #132: the saved free-tier key returned 403 on the full endpoint and 200 on `/free`; the old client mislabeled it as invalid and silently showed empty manual data. Free responses omit per-benchmark scores; retain nulls and existing name matching/ranking. `CW_AA_BASE` points tests at a local stub — never hit the real API in tests.
- `livebench.mjs` (#136, not yet wired into server/delegation): official LiveBench results = livebench.ai `table_<YYYY_MM_DD>.csv` (model × task, 0–100, empty = not run) + `categories_<R>.json`, served from github.com/LiveBench/livebench.github.io `public/`; newest release found via the GitHub contents API of that dir (fallback: cached release). The livebench/livebench repo is the eval framework, not a score feed. Category = mean of task columns, global = mean of categories (as the site). Any malformed file rejects the whole refresh. Cache `<DATA>/livebench.json`, 24 h TTL, 1 h retry after failure; failures keep last-known-good with `stale` + `data_error`; `data_status` ready/loading/unavailable. Mapping: LiveBench name == CLI id/resolved id, or `.agent-orch/livebench-map.json` alias (null = none); LiveBench lists fixed effort configs (`-max-effort`, `-xhigh`), so never alias across effort/version. Evidence: `LIVEBENCH-DATA-CHECK.md`.
- `delegate.mjs`: delegation (BRIEF goal 8). `eligible(task)`: work tasks with `tasks.origin` 'reflection', or 'chat' with `auto_delegate=1` and no `pinned_model` (planTurn sets these from the message's `autoDelegate`/`convo.model`; deferred plan-task messages lose Auto Delegate). `rankCandidates` scores category-weighted AA metrics (`taskCategory`: planner `category` or keywords); comparable = ≥`CFG.delegate.minRatio` or within `rankWindow` ranks. Agents with any `usageLog.current()` window ≥90% are skipped. Curated fallbacks: `convo.fallbacks` ([{agent, model}] | null=auto; PUT `/api/convos/:id/fallbacks`, validated against `modelCatalog`) is snapshotted into `tasks.fallbacks` (JSON) by planTurn only for Auto Delegate messages; a non-null list replaces the ranking (`curatedCandidates`: owner order, availability-filtered, no comparable threshold; `[]` = never delegate). Preview `?convo=` returns it as `candidates` plus `suggested` (automatic top 3). Reflection fallbacks (#142): `projects.reflect_fallbacks` (same JSON, null = auto; PUT `/api/orch/projects/:id/reflect-fallbacks`, server `checkFallbacks` shared with the chat route) is snapshotted into reflection-queued tasks by `finishReflection`; preview `?project=` (start = project's default route). UI: `#obReflect` in `#obPop` (app.js `RF`, `renderReflect`, `rfSave`, `reflectForecast`). `claimNext` delegates a waiting task (sets agent/model, `delegated_from`/`delegated_reason`, clears session_id; retried ≤1/min); orchestrator gets metrics via `modelMetrics` (server: `aaStore.view()`). Manual: `GET/POST /api/orch/tasks/:id/delegate` (`delegateOptions`/`delegateTask`; queued work tasks only, ignores policy/pins); UI `#delegModal` (a `.modal.sheet` = bottom sheet on mobile). Composer Auto Delegate = picker option `__auto`, a per-chat localStorage flag `cw.auto.<cid>` sent as `autoDelegate` with each `send`. While it is chosen, `#apChip` shows `GET /api/delegate/preview?agent=&model=&category=` (orchestrator `delegatePreview` → delegate.mjs `previewDelegation`: start + top 3, usage `status` available/near/limited/unavailable with `note`; limited rank last), refetched on WS `ostate`; `#apModal` lists them. A specific model shows no chip.
- Queue order: `tasks.position` (REAL, per project, lower first) is the primary in-project order (`queueOrder`/`withinProject` in `runnable`); eff breaks ties; plan/reflect/source 'user' and deadline <24 h still go first. New tasks land by eff after their queued prereqs (`insertPosition`). `moveTask` = POST `/api/orch/tasks/:id/move {before|after}`: queued subtree moves as a block, 409 if ahead of a prerequisite; broadcasts `{t:'oorder', project_id, order}`. Task views carry `position`, `prereqs`, `dependents`. UI: `#queueModal` (orch bar `#obQueue`; app.js `Q`, `renderQueue`, `qMove`) drags queued cards with Pointer Events (touch = 350 ms long-press + non-passive `touchmove` preventDefault for iOS; no HTML5 DnD) or Alt+↑/↓; `toast(msg)` is the shared toast. The queued list renders as a tree (`queueTree`: dependents under their queued prereq, `data-parent`, indent ≤48px, connector height `--q-up` set by `qLines`); drops snap to sibling slots only (`qContext().slots`). Mobile width containment lives in `public/app.css` under `#queueModal`/`#qBody`/`#qList`: min-width: 0 on the grid and flex chain, with wrapping dependency text; `public/app.js` keeps the depth indentation. Browser fixture and measurements: `.agent-orch/queue-fixture.html` and `.agent-orch/MOBILE-QUEUE-CHECK.md`.
- `runtimes.mjs`: chat runtime ownership — always use `retireRuntime`, never `q.close()` + `runtimes.delete`.
- `github.mjs`: gh wrapper; every project gets a private repo, pushes go to `origin`. `convo.repo` is just a cache of `gh.remoteOf(cwd)`.
- `public/`: vanilla JS SPA (app.js, marked + dompurify), login page, PWA manifest. Shared `fonts.css` self-hosts Inter + JetBrains Mono; versioned font URLs are public and immutable (sources/conversion in `public/fonts/README.md`). Screenshot TTFs are installed in `~/.local/share/fonts/`.
- `.agent-orch/AGENTS.md`: research notes on the Codex/agy/Gemini CLIs (flags, stream formats, billing env vars to strip).
- Live setup: systemd units agent-orch, agent-orch-shell (ttyd on 127.0.0.1:7682, Caddy at `/shell/`), agent-orch-tmux. `data/` (gitignored) holds auth, convos, metrics, logs, the DB and run logs.

## Conventions
- ESM `.mjs`, no build step, no framework, minimal deps. Match the terse style and comment density.
- Tests: `node --test`; `npm test` runs `test/**/*.test.mjs`. Server tests spawn server.mjs on a free port with `CW_DATA_DIR` set to a temp dir. Orchestrator scheduling tests run `createOrchestrator` in a child process with a fake `query`; CLI adapters are tested with stub binaries in test/fixtures/.
- User-visible times: events carry `until` (epoch s) and a `{until}` token; app.js `withUntil` formats in the browser's timezone. Don't format times on the server except in log lines.
- .agent-orch/AUDIT.md is the bug backlog. When you fix an item, mark it `**Fixed**` with a one-line note.

## Gotchas
- Antigravity #134: native `view_file` uses `AbsolutePath`; snake-casing alone drops it from `toolInputSummary`, so `agyTool` maps it to `file_path`. Run 136's native file reads succeeded; its scheduler conflict, command cancellation and provider 429 are separate. A controlled missing-file read returns a permissions/invalid_args wrapper around ENOENT; the recorded fixture tests error preservation and successful recovery. Evidence: `ANTIGRAVITY-TOOLS.md`.
- This checkout IS the live app. Never restart/kill it or call `POST /api/restart-when-idle` on port 3000 (body `{cancel:true}` cancels a drain). Test instances MUST use another port and `CW_DATA_DIR=$(mktemp -d)`, or they double-run live tasks.
- Edits to server/orchestrator only go live on restart. The UI banner offers "Restart when idle" (drain, exit 0, systemd restarts). A failing "Done when" check may be the running process's stale code (e.g. `extractCommand`), not the task.
- The verifier (`extractCommand`) runs every command-like backtick snippet in "Done when", joined with ` && `. Commands containing `>` (incl. `2>&1`) or `curl` are refused. Absence checks must use `! grep …`.
- `CW_NO_ORCHESTRATOR=1` (preflight on a copy of data/): DB migrated and read APIs served; no lock, orphan requeue, tick loop or git retry push. Still use a spare port and a copied `CW_DATA_DIR`.
- `migrateMemDir()` renames a legacy `.ao2/` into `.agent-orch/`.
- Don't commit macOS `._*` files.
- Auto Delegate popup (#140): starting model, then the reusable `renderFallbackEditor(container, {list, onChange, suggested, catalog, exclude, scoreLabel, ui})` (app.js; `.fe-*` styles): drag via Pointer Events (touch long-press), Alt+↑/↓, remove with Undo toast (`toast(msg, {action, run})`), add, reset. `apSaveFallbacks` is optimistic (chained PUTs, reverts to `AP.confirmed`); the host must skip re-rendering while `ui.busy` (set `ui.stale`, give `ui.refresh`). Browser test: test/ui-fallbacks.test.mjs; bin/shot.mjs `--storage=k=v --click=sel` opens popups for screenshots. The #133 fixture/check (`.agent-orch/delegate-popup-*.mjs`) predates the editor.
- 2026-09-25: Typography uses the system font stack (San Francisco on Apple devices), by the owner's choice. Don't bundle web fonts; a self-hosted Inter was tried and reverted.
