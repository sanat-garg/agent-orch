# Project Context

_What the code doesn't say. History: JOURNAL.md. Bugs: AUDIT.md. Mobile HIG rows: UI-REVIEW.md. Cluster: CLUSTER.md. Computer work: AGENTIC.md. CLI flags and stream formats: AGENTS.md. Setup: README.md. Each module's header comment explains its job and API: read it first._

## Architecture (cross-module rules)
- Head = `server.mjs` (http + ws, chat, `public/`) + `orchestrator.mjs` (node:sqlite DB under `data/orchestrator/`; planner / work / reflection loop; `createOrchestrator({config})` overrides CFG in tests).
- Agents (`agents.mjs`): model lists come only from each CLI (`models.mjs`, cached daily); limits are per agent and never polled. Every discovery/limit/sign-in helper goes through `helpers.mjs runHelper`, never raw execFile.
- Routing: task agent/model → project route → global route → Claude on project.model. Sessions resume only on the agent and node that made them. Delegation moves a task only if its `tasks.fallbacks` snapshot is non-empty; UI wording comes only from app.js `modelStatus(task)`.
- Pause/resume/handoff set `stopIntents`, applied only when the run ended requeued. A paused project keeps its queued plan task until resumed (not a stuck task).
- Keep improving (`projects.perpetual`) off = no reflection at all; planner chat is unaffected. Tests that wait on a reflect task need `perpetual=1`.
- Work tasks run in `<repo>/../.agent-orch-worktrees/<repo>-task-<id>` on branch `agent-orch/task-<id>` (`worktrees.mjs`). Only `mergeTask` touches the main tree, under `serialGit`; every worktrees.mjs git call retries lock races via `retryGit` (never a rebase/merge stopped midway); a rebase conflict → `needs_integration` + an integrator task. Every head push of main or a task branch goes through github.mjs `pushBranch` (one per repo+branch, coalesced, retried, never forced; divergence alerts); never `git push` directly or on a claim's critical path. `tasks.files` (NULL = everything) + `filesOverlap` decide what runs in parallel. `kind='review'` tasks never run.
- Placement: eligible nodes compete by (running + 1) / effective cores, ties round-robin; cores have a floor of 4. Only sustained CPU saturation gates resources (PSI avg60 > 90%, else load1 > 2.5 × cores); RAM/power/heat never gate, owner CPU/task caps remain ceilings; `tasks.run_on` pins one. The owner's Assign (#444, `assignTask`) sets run_on and starts it at once over the node's target (job.offer `assigned`: the worker skips its head-set cap, never its local one); every blocker reason comes from `assignBlocker`, shared with GET …/assignable. Plan/reflect stay local; integrators take a free reserved head slot, else a worker with features `git`+`integrate` (it pushes `agent-orch/integrate-<id>`, the head lands it via the task's worktree + `mergeTask`, ≤ `maxIntegrators` re-integrations); a project without an https/ssh origin goes only to workers with feature `git` (they clone and push through the head's cluster-git.mjs endpoint, GitHub only as a fallback). Lost remote jobs requeue from the pushed WIP branch. Head work slots = kv `parallel_settings.parallelTasks` else `headTarget(cores)`, plus 2 reserved for controller-only work. Memory is only an emergency pause (`MEM.pauseBelow`), never a placement gate (BRIEF goal 9). `CFG.controllerWork` defaults true (the head competes like any node): tests measuring worker-only capacity pass `controllerWork:false`. The per-node verdict helper is `noteDecision` — never name it `decide`, which would shadow the module-level pacing `decide()`.
- Cluster: `cluster-protocol.mjs` holds the wire format, `FEATURES` and `WORKER_ACCEPTS`; change it first, then test/cluster-protocol.test.mjs's expected lists, then CLUSTER.md. `worker.mjs` is compute-only and must never import server/orchestrator/cluster/runtimes: code both sides need goes in `taskrun.mjs` (test/compute-only.test.mjs walks the import graph), including `retryGit`/`transientGit` for lock races and network blips.
- Extensions (`extensions.mjs`) reach runs via files, never argv. `ext.mcpRun(agent, run)` must get the run config (`{browser, gate}`) or the run gets neither the gate nor the browser.
- Browser tasks (`capabilities: ["browser"]`) run the pinned local `@playwright/mcp` (never npx; `ensurePlaywrightMcp` at boot) on a persistent profile, one running task per identity. Exactly one Chromium per profile per node, owned by a detached supervisor (`browser-live.mjs supervise`, state in `control/<id>.browser.json`, stable DevTools port, restarts on crash; Chromium 153 writes no DevToolsActivePort for a fixed port, so launchChrome writes it); the live view and the MCP (via bin/browser-mcp.mjs `--cdp-endpoint`, never `--user-data-dir`) both attach to it. While a task runs the view never re-lays out its page (an override moves what the agent clicks). Headless Chromium: re-apply the metrics override after `Page.captureScreenshot` or input lands at 2× coords. Unpinned browser tasks wait for a Mac while one is online. `agents.mjs browserRun` pre-warms (warmBrowser = startBrowser) and holds the supervised Chromium, gives Claude `MCP_START_ENV` (blocking MCP startup, 90 s) and codex `startup_timeout_sec`, and retries a run whose MCP failed to connect twice before `MCP_START_FAILED`; runs need `browser` passed to runAgentCli for this. The approval gate (`gate.mjs`, `approvals.mjs`, `gate-proxy.mjs`) holds outbound MCP calls for the owner; proxy ↔ host talk only through files; the proxy speaks stdio (`upstream.command`) or MCP streamable http (`upstream.url`), so stdio and http connectors are gated (http re-initializes once when a restarted server 404s a stale session); an sse one with outbound tools is withheld from gated runs. Until AGENTIC.md's run sandbox exists (AUDIT #38) the gate is a log and a speed bump, not a hard stop. Screen prompts (`execution='browser'`) use the non-reflecting Browser project and finish on the final message, without git or checks.
- Update all (#458): cluster.mjs `updateAll` rolls workers one at a time (`node.update` mode 'now'); a worker restores jobs it paused from `update-paused.json` and the head resumes any job a hello lists as `paused`.
- Updates (#426, `rolling.mjs`): Apply updates defaults to 'auto': merged server code (`serverFile`) restarts the head within 2 min even while busy, at most once per 10 min (`<DATA>/restart.json`); only a merge into main in flight holds it (`restartBlocker` = mergeTask's `landingWhile`, waited ≤ `mergeWaitMs` 60 s; never an agent session, #459); preflight first, then `orch.prepareRestart` holds only new HEAD claims (`restartHold`, bounded; worker claims continue, #453), pauses head runs incl. integrators (kv `restart_paused`, resumed at boot) and never touches worker jobs (re-adopted). Pacing/owner caps count ordinary work only (`ordinaryEverywhere`), never integrators; `stateView().stall` is why nothing starts (queue header 'Waiting: …'). A test server whose HEAD moves past `AGENT_ORCH_BOOT_COMMIT` will exit on its own unless set to 'manual'.
- Finish sounds: built-ins are app.js `MACHINE_SOUNDS` (= cluster.mjs `NODE_SOUNDS`); custom ones live in `sounds.mjs` and are picked as `node.sound = 'custom:<id>'`, played from Web Audio buffers preloaded after the audio unlock. The older `/api/settings/sound` MP3 still only replaces the chime (no UI since #481). Settings has only the on/off switch `#stSound` (localStorage `cw.taskSound`) and no About section: sounds and custom sounds are picked per machine in Machines; the About lines (app.js `aboutLines`) are the `#sideVer` tooltip.
- Files API (`files.mjs`) browses the whole disk (absolute paths; relative = the project). Its only guardrails are `PROTECTED` (secrets: listed, never served/copied/moved) and `writeRoots` (project, home, /tmp): any new file op must go through `sourceOf`/`destOf` to get both (and `assertChangeable` if it alters a source in place: rename, delete). Upload (`uploadFile`, POST /api/files/upload, raw body streamed to a temp file then renamed) is the one non-JSON op; server.mjs sets `requestTimeout = 0` so 2 GB uploads aren't cut at 5 min. The client (`public/files.js`) works in absolute paths (`FX.path` = the listing's `dir`); only the Changed view and grep hits stay project-relative, and chat is told `fxRel` paths. The last folder is remembered in memory only (a reload opens the project).
- Build number = `git rev-list --count <sha>` (version.mjs), shown only as version.mjs `formatVersion` (412 → v4.12; app.js `fmtVersion` mirrors it; package.json's version is unrelated); the head sends ws `{t:'version'}` on connect and serves GET /api/version (the sidebar shows it under the logo, `#sideVer`; agent-orch Sign out `#logout` is in the Connections window); workers report `inventory.versions.{sha,build}`.
- `public/`: vanilla JS SPA (app.js ~7k lines, then files/stats/ext/browser.js), classic scripts sharing one namespace (ui-static.test.mjs rejects duplicate functions). Reuse `toast`, `renderFallbackEditor`, `withUntil`, `fmtDur`. The composer's one model pill (#modelChip, #449) is the chat's model + fallbacks control: it opens the shared #fbModal with `chatFallbacks()` (`models: true` adds the Model section); there is no separate Fallbacks button. Phone composer (<768px, #451): only #input (send inside its right edge), #modelChip and #plusBtn show; #plusSheet holds Photo/File and a row per hidden chip (mode, effort, persona) that opens its .cmenu above '+' via app.js `openMenuFrom(chip, anchor)` (test/ui-mobile-composer.test.mjs). Settings live in the gear's Settings sheet; #orchBar stays minimal (app.js `orchBarStatus`: 'Running X · Queue Y' / 'Paused · Queue Y' / 'Idle'; the Queue button has no count). Web Push goes only through server.mjs `notify`; `public/sw.js` is push-only: never add a fetch handler or caching (stale shell). `#task-<id>` links (push, SW `open` message) go through app.js `routeHash`. ## Conventions
- ESM `.mjs`, no build step, no framework, minimal deps. Match the terse style and comment density.
- Tests: `npm test` runs only the test files the diff from main can reach; `npm test -- test/x.test.mjs` runs named files; `npm run test:full` is for reflection only. Verify with the files you touched; the orchestrator runs Done-when itself. Copy a neighbouring test's setup (server tests spawn server.mjs on a free port with a temp `CW_DATA_DIR`; scheduler tests use `createOrchestrator` with a fake `query`; UI tests use playwright-core). The VPS has no `init.defaultBranch`: a bare test origin's HEAD is `master`, so clone it with `-b main`.
- Times: events carry `until` (epoch s); app.js `withUntil` formats in the browser. Never format times on the server except in logs.
- AUDIT.md items get `**Fixed**` + a one-line note; UI-REVIEW.md rows are marked fixed in place.
- Mobile: Apple HIG (apple-design skill). Phone header (<768px, #450): one 44px row with ≤3 controls (#openSidebar, the title #viewBtn whose #viewMenu holds the views and the overflow, e.g. the repo link, and #topAction); .seg/#cwdLabel/#repoLink are hidden there, so phone tests switch views via #viewBtn → `#viewMenu [data-view]` (test/ui-mobile-header.test.mjs). Modals need `grid-template-columns: minmax(0, 100%)`. 44px touch targets and 16px fields go in `@media (pointer: coarse)` blocks after the base rule; phone type sizes in the `max-width: 600px` block at the end of app.css. Filled buttons use `--accent-strong` (test/ui-contrast.test.mjs asserts ≥ 4.5:1 in both themes).
- macOS shell scripts must parse under bash 3.2 (test/install-macos-bash32.test.mjs): no `declare -A`, `mapfile`, `${x,,}`, `|&`, `local -n`; `cmd <<EOF`, not `cat <<EOF | cmd`; under `set -u` an empty `"${arr[@]}"` is unbound.

## Decisions (beyond BRIEF.md)
- Subscriptions only: API_ENV stripping in server.mjs is what enforces it. Never weaken that.
- Local branch `backup/pre-agent-orch` must never be pushed. Local `claude/*` branches and `agent-orch/task-197/-199/-209` are the owner's unlanded work: never land or delete them unasked.
- `after` is for TRUE prerequisites only (cancelling cascades). Use `files` to keep parallel work apart. Rapid top-up (`rapidQueue`) targets free worker slots + 2 minus worker-ready work; head-only work (integrators, tasks kept on the head) and chained tasks never count. In Rapid mode file overlap never blocks a free slot (only the per-file cap does: kv `file_caps`, tuned from kv `file_merge_outcomes`); Rapid off = strict overlap gate. A merge conflict is retried once (CFG.conflictRetryMs) before an integrator. Overlap never requeues a running task; a running task going back to `queued` is a worker reject/loss, crash, limit or owner stop.
- System font stack only. No benchmark ranking of models, ever.
- Computer work follows AGENTIC.md's rollout (files-only workspace first). Connectors (Gmail etc.) only when the owner asks.

## Gotchas
- This checkout IS the live app. Never restart/kill it or call `POST /api/restart-when-idle` / `/api/restart-now` on port 3000. Test instances MUST use another port and `CW_DATA_DIR=$(mktemp -d)`. Server edits go live only on restart: a failing Done-when may be stale running code, and new DB tables don't exist until then.
- The verifier runs every command-like backtick snippet in Done-when (a whole runner word), joined with ` && `; `>` (except `2>&1`, `2>/dev/null`), `curl` and more than three `&&` are refused; `CI=1 ` and `cd <relative dir> && ` prefixes are fine. Absence checks use `! grep …`. A `|` inside a quoted grep pattern is regex, not a pipe.
- /tmp is a small tmpfs with a per-user quota; run heavy tests with `TMPDIR=` on the home disk. test/helper-kill.test.mjs is racy under load and can leave `test/fixtures/helper-parent.mjs` holding the shared test lock: kill that pid. Without `flock` (the MacBook) bin/test.mjs locks with `node_modules/.cache/agent-orch-test.lock.d`.
- On a macOS worker some suites fail regardless of the change (compute-only's `/proc` check, cluster.test's controller-slot sizing, UI tests' `renderMetrics` page error; cluster-ping-ui.test.mjs filters it). On Sanat's MacBook every Playwright browser dies at launch (SIGILL; Chrome: `Mach rendezvous failed`), so UI tests skip or fail there: check UI logic with a vm test (task-sound, ui-machines-settings), a jsdom harness outside the repo, or put UI text in a pure app.js helper tested from source (version-ui tests). Browser e2e tests (and ui-files-manage) inject `test/helpers/mac-chromium.mjs`'s shim via `chromium.launch({env})`, which makes a UI test really run there; Chrome for Testing `--headless=new` (findBrowser) runs. bin/shot.mjs runs there with `DYLD_INSERT_LIBRARIES=node_modules/.cache/mac-chromium/wm-shim.dylib` exported in the calling shell (SIP strips DYLD_* through /bin/bash, so don't wrap it in `bash script.sh`). Headless Chromium screencasts at its screen's scale, not the emulated deviceScaleFactor: browser-live.mjs's `--screen-info` makes it 2×.
- node:test `mock.timers.tick(n)` never runs a timer that a timer it ran scheduled within the same tick: step time in small increments (test/ui-ping-result.test.mjs `tick`).
- `bin/agent-smoke.mjs` and `bin/orch-e2e.mjs` cost quota; never send Claude logout (`confirm: true`) in tests.
- Other sessions and orchestrator auto-commits touch the live checkout at once: re-read before editing. A branch failing in files you didn't touch is usually a stale snapshot base: fast-forward the worktree to main and re-run.
- Reflections: run the needed tests to a log first and emit the task block in the final message; never end the turn waiting on a background job. Check which files queued and running tasks hold before queuing; when AUDIT.md is held, queue the code fixes without it and one ledger task `after` them.
- 2026-09-28: Every machine card and machine detail panel keeps an 'Assign task' button (renderAssignButton(node) in public/app.js). Any redesign of the Machines UI (#382, #433, #434) must keep it. The all-machines window opens only through app.js `openMachines()` (sidebar card, #447); #382's full-screen view replaces its body.
