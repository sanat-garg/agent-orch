## Prompt

URGENT: the owner is blocked installing a Mac worker. `curl -fsSL https://129-154-229-134.sslip.io/install/worker-macos.sh | sudo bash -s -- --controller … --code … --agents claude,codex` fails right after '==> Setting up the worker as agentorch' with `bash: -c: line 208: syntax error near unexpected token |`. Root cause (reproduced by the planner with a locally built bash 3.2.57, the exact macOS /bin/bash, at /tmp/b32/bash-3.2.57/bash): bin/install-worker-macos.sh line ~409 ships its functions to the dedicated user with `sudo -u "$WUSER" -H bash -c "set -euo pipefail; $vars; $(declare -f); cd; worker_stage"` (and again for node_path on ~410). Bash 3.2's `declare -f` prints the construct at line ~296, `cat <<EOF | write "$plistf"`, with the `| write "$plistf"` AFTER the EOF terminator line, so re-parsing fails. Bash 5 (this server) prints it correctly, which is why the tests passed. Fix: 1) Change line ~296 to `write "$plistf" <<EOF` (a here-doc redirected straight into the function), and remove every other `cat <<… | …` pattern in both installer scripts. The planner verified that with this single change, bash 3.2 re-parses `$(declare -f)` cleanly and `bash3.2 install-worker-macos.sh --dry-run …` exits 0 with and without --no-dedicated-user. 2) Make bash 3.2 a permanent test tool: add bin/dev/build-bash32.sh, which downloads bash-3.2.57 from ftp.gnu.org, builds it (`sudo apt-get install -y bison`; `./configure --build=aarch64-unknown-linux-gnu --without-bash-malloc --disable-nls`; `make CFLAGS="$F" CFLAGS_FOR_BUILD="$F"` with F='-O1 -std=gnu89 -Wno-implicit-function-declaration -Wno-implicit-int -Wno-int-conversion -Wno-incompatible-pointer-types -Wno-error'; delete the shipped y.tab.c/y.tab.h first so bison regenerates them) and installs it to ~/.local/opt/bash-3.2.57/bin/bash. Copy the already-built /tmp/b32/bash-3.2.57/bash there now if it still exists. 3) Add test/install-macos-bash32.test.mjs (it skips with a clear message if the bash 3.2 binary is missing): (a) with the script's functions loaded into bash 3.2 WITHOUT running main, it asserts that `bash3.2 -n -c "set -euo pipefail; $vars; $(declare -f); cd; worker_stage"` succeeds. To load the functions without running main, add a guard such as `[[ -n "${AGENT_ORCH_INSTALLER_NO_MAIN:-}" ]] || main "$@"`, and do NOT use "${BASH_SOURCE[0]}" for this, because with `curl | bash` under set -u, bash 3.2 treats it as unbound. (b) It asserts that `bash3.2 bin/install-worker-macos.sh --dry-run --controller https://x --code TEST --agents claude,codex` exits 0 with no 'syntax error'/'unbound variable' in its output, for both the dedicated-user and --no-dedicated-user modes. (c) The same checks for bin/install-worker.sh (Linux uses bash 5, but keep it 3.2-safe too). 4) Scan both installers for other bash-3.2 hazards (empty "${arr[@]}" under set -u, `declare -A`, `mapfile`/`readarray`, `${x,,}`/`${x^^}`, `|&`, `;;&`, `local -n`) and fix any you find. The server serves bin/install-worker-macos.sh fresh from disk (server.mjs ~line 1329), so no restart is needed once this is merged. Don't touch data/.
