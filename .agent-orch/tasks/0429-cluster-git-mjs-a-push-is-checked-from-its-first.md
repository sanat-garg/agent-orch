## Prompt

Harden the head's git endpoint for paired workers, cluster-git.mjs (read its header; BRIEF goal 11; .agent-orch/CLUSTER.md). Two problems, both in `handle`: (a) a git-receive-pack POST is read whole by `readAll` (up to MAX_PUSH_BYTES = 1 GiB) into memory before the command list is checked and before git sees a byte. The head is a 1-core VM whose memory is the emergency brake for every running task, so one big push from a worker can starve everything. Fix: read the request incrementally, buffering only until `pushedRefs` can decide (the command list ends at the first flush pkt `0000`; keep buffering while it returns null and the buffer is under a small cap such as 1 MiB, then refuse with 400 'unreadable push' if still undecidable), refuse with 403 exactly as today when a ref is not the node's own task branch (and drain/destroy the request without reading the rest), and otherwise spawn `git http-backend`, write the buffered prefix to its stdin and pipe the remainder of the request into it. Keep CONTENT_LENGTH from the request header (or omit it when chunked) instead of the buffered length. Keep the gzip path (git only gzips upload-pack requests, so a gzipped receive-pack is rare): buffer a gzipped push up to a 64 MiB cap, gunzip, check, then feed it whole as today; over the cap answer 413. Drop or shrink MAX_PUSH_BYTES accordingly, keeping the export if tests import it. (b) When the client socket closes before the CGI finishes (a worker that loses the network mid-clone), nothing kills the CGI and `res.write` keeps being called on a dead response: on `res.on('close')` / `req.on('aborted')` kill the child if it is still running, and stop writing. Tests in a NEW file test/cluster-git-stream.test.mjs, copying test/cluster-git.test.mjs's setup (a temp bare-ish project repo, `createClusterGit` with a fake `node`/`repo`/`pushable`, http.createServer routing to `handle`): (1) a push of a branch with a multi-megabyte blob (e.g. 8 MiB of random bytes committed in a temp clone) from a permitted task branch succeeds and process memory growth stays well under the pushed size — simplest is to assert the prefix buffer never exceeded the cap by exposing it via a `log` message or an option; alternatively assert `process.memoryUsage().rss` grows by less than the blob size; (2) a push to `refs/heads/main` is refused with 403 without the body being read whole (the server answers before the client finishes sending: make the client send a large chunked body slowly and assert the 403 arrives first); (3) a raw request whose first 1 MiB has no flush pkt gets 400; (4) starting a clone and destroying the client socket mid-response leaves no `git` child (poll `ps` / the child's exit within 5 s). Keep test/cluster-git.test.mjs and test/cluster-git-e2e.test.mjs passing; run only those three files.
